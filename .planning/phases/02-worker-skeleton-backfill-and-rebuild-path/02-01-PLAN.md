<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend lifecycle to worker process | The main Codi process can launch/schedule a local worker but must not block on worker work. |
| worker state files to request-path status | Status reads derived worker metadata and must sanitize failures before returning HTTP JSON. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Denial of Service | web startup and event loop | mitigate | Supervisor launch returns quickly; tests prove `start_web_server()` does not await full backfill. |
| T-02-03 | Tampering | worker status state | mitigate | State helpers write only under `CODEXBOT_DIR/search`; tests prove `monitor_state.json` is unchanged. |
| T-02-05 | Denial of Service | request-path imports | mitigate | Keep worker/model/index imports out of `src/codexbot/web/api.py`; static import-boundary tests enforce it. |
| T-02-06 | Information Disclosure | status reason | mitigate | Sanitize worker errors before status exposure; tests reject raw transcript text, secret names, and stack traces. |
</threat_model>
