# Phase 02 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase UI Boundary

Phase 02 is a backend and worker phase. It must not add Web UI search controls,
search result rendering, hit navigation, rebuild buttons, or new browser-side
indexing behavior. Existing Web UI, Telegram, terminal, and WebSocket surfaces
must remain usable while backend search backfill runs.

If implementation touches Web UI-adjacent copy or status payload labels, it must
follow the existing custom Codi Web UI design system below and keep the visual
surface quiet, operational, and status-oriented.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | custom React components in `web-ui/src/components/` |
| Icon library | `lucide-react` |
| Font | `Roboto` for UI text; `Roboto Mono` for terminal/code text |

Design-system decision: do not initialize shadcn in Phase 02. The repo has an
existing Vite React Web UI with custom tokens in `web-ui/src/styles.css`, and
this phase does not implement frontend components.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, compact status separators |
| sm | 8px | Compact element spacing, input padding, toolbar gaps |
| md | 16px | Default panel padding and form grouping |
| lg | 24px | Empty/status state padding and sidebar section spacing |
| xl | 32px | Modal/card padding where existing UI already uses it |
| 2xl | 48px | Major section breaks only |
| 3xl | 64px | Page-level spacing only |

Exceptions: existing CSS has 6px button/icon gaps and 10px input/list padding.
Do not introduce new spacing exceptions in Phase 02.

---

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#15161a` | App background and full-height shell |
| Secondary (30%) | `#1a1c20`, `#1f2126`, `#22242a` | Sidebar, panels, inputs, elevated surfaces |
| Accent (10%) | `#a78bfa` | Links, active selection markers, focus affordances, primary action only if an existing control is reused |
| Destructive | `#ff6b8a` | Destructive actions and error/severe failure text only |

Accent reserved for: existing links, active session selection, focus states,
primary action buttons already styled as `button.primary`, and future status
chips for `building` or `ready` only when those states become visible in a UI
phase. Do not use accent for all buttons or all interactive elements.

Status semantics if copy is surfaced:
- `missing` / `unavailable`: neutral text color `#c4c4c9`.
- `building`: warning color `#ffb454` or accent only for a small status chip.
- `failed` / worker error: destructive color `#ff6b8a`.
- `ready`: success color `#4ed4a0`.

---

## Visual Hierarchy And Interaction Scope

Primary focal point for Phase 02 remains the existing selected session and chat
content. Search backfill status must not become a new dominant visual element in
this phase.

If a status label is exposed through existing development/status surfaces, it
should be secondary to the current session workflow: compact text or a small
chip, no modal, no blocking banner, no landing page, and no animated or
decorative treatment.

Icon-only controls are not introduced in Phase 02. If later phases add them,
they must use `lucide-react` and include accessible labels or tooltips.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | No new primary CTA in Phase 02. If an existing operator/status control is reused, use `Refresh Search Status`. |
| Empty state heading | `Search index is not built yet` |
| Empty state body | `Codi is preparing local search from open sessions. Existing sessions and messages remain available.` |
| Error state | `Search indexing is unavailable. Existing sessions still work; check the local service logs and retry rebuild.` |
| Destructive confirmation | No destructive Web UI actions in Phase 02. Explicit local rebuild is CLI-only and does not need browser confirmation copy. |

Copywriting constraints:
- Do not use `No data found`, `Something went wrong`, `Submit`, `OK`, or
  single-word CTAs for search status states.
- Make readiness states distinguish missing, building, unavailable, and failed.
- Never imply search results are ready before retrieval exists.
