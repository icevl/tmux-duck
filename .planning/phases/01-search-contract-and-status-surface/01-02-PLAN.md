## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local state directory to search provider | Provider reads optional derived metadata under `$CODEXBOT_DIR/search/` and must not trust or mutate authoritative Codi state. |
| API route to provider | Later routes call provider functions that must remain dependency-light and safe on the request path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | Search API auth | transfer | No route is created in this plan; `01-03` must require existing Web UI auth. |
| T-01-02 | Denial of Service | `SearchRequest` provider input | mitigate | Provider accepts only validated `SearchRequest` DTOs from `01-01`; no unbounded raw query strings are accepted. |
| T-01-03 | Information Disclosure | `get_status` and `search` responses | mitigate | Missing-index responses expose state, scope, reason, counters, and generation metadata only; tests reject secrets, raw transcript content, and raw local paths. |
| T-01-04 | Tampering | search state helpers | mitigate | State helpers resolve and read only under `$CODEXBOT_DIR/search/`; tests prove `monitor_state.json` remains unchanged. |
| T-01-05 | Denial of Service | provider imports | mitigate | Provider remains dependency-light and is covered by the AST import-boundary test from `01-01`. |
</threat_model>
