<objective>
Create the durable search live-queue state layer that can persist queue rows,
leases, retries, failures, and transcript watermarks under `CODEXBOT_DIR/search`
without affecting existing Codi session or monitor state.

Purpose: Phase 3 needs an idempotent, inspectable, restart-safe queue foundation
before monitor events or worker draining can rely on it.
Output: Queue contracts/state helpers, SQLite-backed queue module, status
integration for queue lag/failures, and tests covering durability and dedupe.
</objective>

## Phase Goal

**As a** Codi Web UI user, **I want to** new transcript items to be durably
queued without slowing normal chat delivery, **so that** search can catch up
after backfill, restarts, or transient worker failures.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| transcript-derived document to queue DB | Local transcript content becomes durable queue rows and must not duplicate or corrupt identity. |
| queue DB to Web API status | Request paths read summarized queue state only and must not leak raw transcript payloads, local paths, secrets, or stack traces. |
| search queue state to authoritative Codi state | Queue leases/retries/watermarks are derived search state and must not mutate session or monitor state files. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | queue state location | high | mitigate | Store `queue.sqlite` only under `CODEXBOT_DIR/search`; tests assert `monitor_state.json` and `state.json` are unchanged. |
| T-03-02 | Tampering | queue/document identity | high | mitigate | Use deterministic queue ids plus `SearchRowIdentity`; tests prove duplicate enqueue is idempotent and routing metadata is not identity. |
| T-03-03 | Denial of Service | leases and retries | medium | mitigate | Persist lease expiry, attempt counts, and dead-letter state; bounded retries prevent permanent poison rows from blocking all batches. |
| T-03-04 | Information Disclosure | status reason | high | mitigate | Expose counts and sanitized recent errors only; tests reject raw transcript text, secret names, full stack traces, and local transcript bodies. |
</threat_model>
